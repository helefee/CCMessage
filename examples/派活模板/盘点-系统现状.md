# 模板：盘点一个大系统（开新系列前用）

先读 `00-通用规矩.md`。用在「这个系统一共有多少东西、我们做了多少、按什么顺序拆卡」这类开系列前的摸底。

## 派活时填的参数

- **系统**：名字
- **建议卡号前缀**：先 `python <总线>/bus.py claim list` 看有没有撞
- **交回目录**：`<项目>/out/<系统>/`

## 要做的事

1. **全量清单**：这个系统的所有条目（表、功能点、界面、接口），逐条带出处；数目要对得上（写出计数命令）。
2. **规则摘要**：只抓总规则，细节留给单卡调研。
3. **本项目现状**：每条目 做了 / 做了一半 / 没做，**每条都带 grep 证据**；也查计划和进度文档里有没有立过项。
4. **依赖与地基**：需要哪些还没有的底座，和已有模块的牵连（同一个文件 / 接口别处在用）。
5. **拆卡与排序**：从易到难排，每张卡写「做什么 / 依赖谁 / 大概几个单元 / 要人定的口径」。做不了或不该做的单列「不做」并写理由。

## 交回什么

`<交回目录>/00-盘点与拆卡.md`（总结论 + 排序表 + 不做清单 + 要人定的事），细节可拆成几份。

交活消息：条目总数、已做 / 没做、建议第一张卡、要人定的事几条。
