# 模板：开卡前调研

先读 `00-通用规矩.md`。只查、只报，不改代码。

## 派活时填的参数

- **对象**：要做的功能 / 模块 / 接口
- **交回目录**：`<项目>/out/<卡号>/`
- **额外问题**（可选）：派活方特别想知道的几条

## 要做的事

1. **原始出处**：源码 / 数据表 / 官方文档里跟这个对象有关的全部条目，逐条带 `文件:行` 或 URL。数目要能对上（写出计数命令）。
2. **现状**：本项目已经做了哪些、做了一半的、没做的，每条都带 grep 证据。
3. **口径**：规则、数值、边界（次数、时限、失败时怎样、断线重连怎样），照原文写，别简化。
4. **牵连**：会碰到哪些已有模块、别人正在做的（`python <总线>/bus.py claim list` 看占号）。
5. **开放问题**：原文说不清、要人定的，逐条列出，可以写你的倾向但别自己定。

## 交回什么

`<交回目录>/research.md`：结论速览（10 条以内）→ 逐条细节（带证据档和出处）→ 现状表 → 开放问题。

交活消息：结论速览里最要紧的 3 条 + 报告路径 + 开放问题几条。
