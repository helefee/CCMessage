# 派活模板（通用骨架）

把「调研、复核、验证、独立单元、盘点」这类不需要派活方上下文的活，按固定模板派给 Codex / Cursor / 别的 Claude 会话。
派活方只填参数；接活方读模板照做；交回后派活方照「收活检查」抽查再用。

**用法**：把这个目录复制到项目的总线目录（`<项目>/.msgbus/派活模板/`），把 `00-通用规矩.md` 里「不许碰什么」「产物放哪」改成你项目的，
再按需要补项目专用的模板（例如「调研-某模块」）。项目专用的留在项目里，别往这里塞。

| 文件 | 用在什么时候 | 交回 |
|---|---|---|
| `00-通用规矩.md` | 每个模板都先读：语言、产物位置、不许碰什么、证据口径、交活方式 | — |
| `调研.md` | 开一张新卡前查资料（源码 / 文档 / 官方说明） | `<交回目录>/research.md` |
| `盘点-系统现状.md` | 开一个新系列前摸底、拆卡 | `<交回目录>/00-盘点与拆卡.md` |
| `实现-独立单元.md` | 计划里标了「可派活」、不和派活方改同一批文件的单元 | 分支 + 提交 / PR 号 + 测试结果 |
| `复核-代码改动.md` | 写完后换个模型再看一遍（第二双眼睛） | `review-<模型>.md` 问题清单 |
| `验证-测试.md` | 全量测试 / 长时间验证 | 过 / 新红清单 |

## 怎么派

```bash
python .msgbus/bus.py task --to codex "按 .msgbus/派活模板/调研.md 做（先读同目录 00-通用规矩.md）。对象=支付回调；交回目录=out/pay-cb/；额外问题：重试间隔是多少"
```

两件互不相干的活可以同时派给两个对话；Codex 没开时（退出码 3）交给 Claude 子代理，把同样一句话当提示词。

## 收活检查（派活方必做，别直接信）

1. **抽查出处**：结论里挑 3 条，打开它写的 `文件:行` 看原文是不是这么说。
2. **「没有 X」类结论自己 grep 一次**。
3. **看口径有没有被降级**：原文写着「第 N 次 / 剩余 M 分钟」的，交回里不能变成「不限」。
4. **看开放问题**：要用户定的，汇总后一次问用户；接活方写的「倾向」只作参考。
5. 复核报告里标「崩 / 错」的，自己复现一遍再修。
