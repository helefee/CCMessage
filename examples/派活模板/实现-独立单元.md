# 模板：实现一个独立单元（计划里标了「可派活」的）

先读 `00-通用规矩.md`。只做计划里这一个单元；**和派活方正在改的文件不重叠**才派得出来，接活时自己再确认一遍。

## 派活时填的参数

- **计划**：计划文件路径 + 单元号
- **基于哪条分支 / 提交**
- **你的分支 / worktree**：`feat/<卡名>-<单元>`，`<worktree 目录>/<短名>`
- **只许改的文件**：清单（超出就停下问）
- **交回**：PR 号（base 指向派活方的分支，不是主干）或推送的提交号 + 测试结果

## 要做的事

1. `git worktree add -b <你的分支> <worktree 目录>/<短名> <基点提交>`。
2. 读计划里这个单元的「要做什么 / 测什么 / 边界」和它引用的调研。**口径照调研原文**，没写清的写成问题交回，别自己定。
3. 跟着周围代码的写法写：命名、注释密度和旁边一样；有生成器的数据改生成器再重新生成，别手改生成物。
4. **同一刀带测试**：测试要能被变异抓住（改一行实现，测试要红）。
5. 在自己的 worktree 跑本单元测试 + 受影响的老测试；全绿再提交。
6. 推送自己的分支；要开 PR 的，base 设为派活方的分支。**不要合并任何东西。**
7. 删 worktree 之前先确认已推送。

## 交回什么

交活消息：分支名 + 提交号（或 PR 号）、改了哪些文件、测试结果（条数 / 全绿）、计划里没说清楚你是怎么处理的（逐条）。
