# 模板：跑耗时验证（全量测试 / 长时间验证 / 变异对照）

先读 `00-通用规矩.md`。只跑、只报，**不改代码**（发现红了也不修，报回来）。

## 派活时填的参数

- **被测树**：分支 + 提交号（或派活方给的副本目录）
- **跑什么**：全量测试 / 指定清单 / 变异对照脚本
- **对照基线**（可选）：主干的某个提交，用来区分「这次弄红的」和「主干本来就红的」

## 要做的事

1. **不要在派活方的工作树里跑**（测试可能改工作树）：用 `git archive <提交> | tar x -C <目录>` 拷一份，或自己建 worktree。
2. 按要跑的东西执行，记下命令、退出码、最后几行输出。
3. 有红的：同样的命令在**对照基线**上再跑一次，分清「基线也红」和「这次新红」。
4. ★ 不连任何生产 / 测试服务器（除非派活明写）。

## 交回什么

`<交回目录>/verify-<日期>.md`：总结果一行、新红清单（测试名 / 输出末几行）、基线也红的清单、变异体抓到几个 / 没抓到哪几个、完整日志路径。

交活消息：`全过` 或 `新红 N 条：<名字>…` + 报告路径。
