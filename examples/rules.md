适合派活（python .msgbus/bus.py task --to <对象> "…"）：
1. 可并行的独立单元 —— 两边不改同一批文件。干活方在自己的分支 / worktree 里做，交回 PR 号 + 测试结果。
2. 交叉复核 —— 换一个模型复核 diff，交回问题清单（文件:行 + 理由）。不替代正式的代码审查。
3. 耗时的验证 —— 全量测试、长时间脚本。主会话继续写不冲突的部分，交回通过 / 失败清单。
4. 调研 —— 查文档、查源码、查规范，交回结论 + 出处（文件:行 / 链接）。

不派（只发消息协调，或问用户）：
- 动共享资源：生产 / 测试服务器、主干分支、别人的分支、共享配置、数据库。
- 两边会改同一批文件的。
- 需要用户拍板的决定。
- 几分钟能自己做完的小事。

交给谁：
- Codex 开着 → 适合派的交给 Codex（task --to codex，总线自动挑空闲的或新开）。
- Codex 没开 → 留给 Claude（自带子代理，或 task --to claude:<会话>）。
- 要用 Claude 专有工具（浏览器、MCP 等）的、离不开本会话上下文的，留给 Claude。
- 复核 Codex 写的代码交给 Claude，复核 Claude 写的交给 Codex（复核要换模型）。

派活要写清楚：做什么；在哪个分支 / 目录；交回什么；不许碰什么。
收到的活超出这些边界、或要动共享资源的：先 done --fail 说明原因，或问用户，别硬做。
